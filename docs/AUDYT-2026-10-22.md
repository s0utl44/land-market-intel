# Przegląd pracawre.com – bezpieczeństwo, spójność, co dalej (22.10.2026)

Zakres: portal, Radar działek, Generator umów, Protokoły, logowanie Google, Traefik, kopie zapasowe.
Nic krytycznego nie było otwarte z internetu: wszystkie podstrony są za logowaniem Google (tylko @wrenieruchomosci.pl),
bazy i usługi wewnętrzne nie są wystawione na zewnątrz, nagłówka z e-mailem nie da się podrobić przez Traefika.
Najpoważniejsze luki dotyczyły pracownika, który już jest zalogowany (np. przejęte konto) – i te są poprawione.

## 1. Poprawione dziś (w repozytoriach, działa po wgraniu na serwer)

### Generator umów
- **Wstrzyknięcie skryptu przez plik umowy (XSS)** – spreparowany plik umowy zapisany przez jedno konto mógł uruchomić
  kod u osoby, która go otworzy (np. u admina) i pobrać całą bazę klientów. Identyfikatory z pliku są teraz sprawdzane
  i escapowane.
- **Zapis poza folderami aplikacji** (stary sposób zapisu `zapiszUmowe` z `..`) – zablokowany, tylko pliki .docx.
- **Limity rozmiaru** – plik do 25 MB, zapytanie do 60 MB (wcześniej bez limitu = ryzyko zapchania dysku).
- **Zgłoszenia** – nie-admin nie może już nadpisać ani usunąć cudzego zgłoszenia.
- **Profile pośredników** – cudzy profil zmienia/usuwa tylko admin; nikt nie przypisze sobie cudzego konta Google.
- Szybsze wejście: strona (1,5 MB) pobierana ponownie tylko po aktualizacji aplikacji (ETag).

### Protokoły
- **Wgrywanie plików** – tylko zdjęcia (JPG/PNG/WEBP/HEIC/GIF) rozpoznane po zawartości; wcześniej dało się wgrać
  stronę HTML/SVG, która w tej samej domenie działałaby jak strona pracawre.com (przejęcie sesji admina).
  Pliki podawane z blokadą wykonywania (`sandbox`, `nosniff`). Limit 20 MB.
- **Analiza AI** – każdy zalogowany mógł zmienić wynik analizy cudzego protokołu i dopisywać analizy do dowolnego
  protokołu; teraz obowiązują te same uprawnienia co w aplikacji.
- **Pobieranie obrazów przez serwer** – serwer pobierał dowolny podany adres (SSRF); teraz tylko zdjęcia z magazynu.
- **ClickUp** – zadanie tylko dla własnego powiadomienia (albo admin) i tylko raz.
- **Linki do zdjęć** – ważne max 1 h (było 7 dni) i nie działają jako przepustka do bazy.
- **Rola „bez logowania” (anon) w bazie** – odebrane wszystkie uprawnienia; przywrócone ograniczenia funkcji z Lovable.
- Baza i PostgREST oznaczone jako niewidoczne dla Traefika. Usunięty przykładowy kod z Lovable.
- Nagłówek: krótsze etykiety bez zawijania, wylogowanie tylko we wspólnym pasku, „Admin” także w menu na telefonie.

### Radar, portal, serwer
- Nagłówki bezpieczeństwa dla wszystkich podstron: Referrer-Policy, Permissions-Policy, podstawowa CSP, HSTS
  z subdomenami.
- Radar: linki z ogłoszeń i zgłoszeń tylko `http(s)` (blokada `javascript:` z cudzych danych).
- Kopia zapasowa: przerywa się, gdy zrzut bazy jest podejrzanie mały – rotacja nie usunie wtedy dobrych starszych kopii.

## 2. Do zrobienia na serwerze (Ty, ~15 min)

1. Wgranie zmian:
   ```
   cd /opt/lmi && git pull && docker compose build web && docker compose up -d
   cd /opt/umowy && git pull && docker compose up -d --build
   cd /opt/protokoly && git pull && docker compose up -d --build
   ```
2. Sprawdzenia (wyślij mi wynik):
   ```
   grep -c LMI_DB_PASSWORD /opt/lmi/.env
   docker inspect traefik-traefik-1 --format '{{json .Args}}' | tr ',' '\n' | grep -i -E 'exposedbydefault|forwardedheaders|api'
   docker --version
   grep -E '^(PermitRootLogin|PasswordAuthentication)' /etc/ssh/sshd_config
   ufw status | head -5; systemctl is-enabled unattended-upgrades fail2ban 2>&1
   ```
3. Konto Hostinger: włączyć logowanie dwuskładnikowe (2FA), jeśli nie jest.

## 4. Plan ulepszeń (proponowana kolejność)

**Generator – teraz, gdy nie jest już w Apps Script**
1. Polisy jako osobne pliki zamiast wbudowanych (strona ~1 MB lżejsza, nową polisę wgrywa admin bez przebudowy). S
2. Ochrona przed równoczesną edycją (dwie osoby w tej samej umowie – teraz wygrywa ostatni zapis). M
3. Kosz i historia wersji w aplikacji (dane już są zapisywane, brak widoku „przywróć”). M
4. Wyszukiwarka umów na serwerze (adres, klient, pośrednik, data) zamiast ładowania całego drzewa. M
5. Połączenie z Protokołami: wybór mieszkania / właściciela / najemcy z bazy protokołów przy tworzeniu umowy. M
6. PDF na serwerze (identyczny w każdej przeglądarce, koniec obejść dla Safari, podstawa pod wysyłkę e-mail). M
7. Wysyłka umowy e-mailem do klienta z serwera (zamiast szkiców Gmaila przez Apps Script). M
8. Podział 4900-linijkowego app.html na moduły + testy szablonów. L

**Bezpieczeństwo – dalsze kroki**
1. Tajny nagłówek między Traefikiem a aplikacjami (dziś proces na serwerze mógłby podać dowolny e-mail bezpośrednio). S
2. Pełna CSP (wymaga przeniesienia skryptów inline). M
3. Kontenery bez roota, przypięte wersje obrazów, regularne aktualizacje (Metabase, oauth2-proxy). S
4. Kopie: szyfrowanie z kontrolą integralności (age), alert e-mail przy błędzie, test odtworzenia raz na kwartał. S
5. Monitoring dostępności z zewnątrz (np. UptimeRobot) – dziś awarię zauważy dopiero użytkownik. S
6. Protokoły: odebranie admina po usunięciu z listy PROTOKOLY_ADMINI; token ClickUp zaszyfrowany. S

**Spójność wszystkich paneli**
- Wspólny pasek, motyw i przejścia – zrobione. Dalej: wspólne komponenty (przyciski, karty, okna, komunikaty),
  ten sam układ nagłówka podstrony, tłumaczenie i wygląd komunikatów błędów, jeden ekran „Brak dostępu”.
